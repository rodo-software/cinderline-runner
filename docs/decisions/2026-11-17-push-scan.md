# The push scan, built against a contract change the app makes first

- **Status:** Accepted
- **Date:** 2026-11-17
- **Source:** Willem on CLR-190 (choice A, "build to proposal"), building point 2 of decision 2026-11-17-open-questions-answered.

## Decision

1. **The runner side is built now against the contract change below; it merges after the app ships that change.** The app refuses an outcome it does not know with `422`, so a runner with the scan that reports a hit to an app without the change loses that report. The change starts in the app repository; `docs/runner-api/openapi.yaml` here is copied from there afterwards, not edited first.
2. **Where.** `Workspace.Push` scans, so every push is covered: publish, stop, after a sub-issue, before a check, before a clone is replaced, stranded branches and Review branches. The helper fetches the agent's branch, runs `git log -p` on every commit no other remote branch has (also merge commits, as the difference from git's own merge) and looks at each commit's header, message and added lines. A value `internal/redact` holds, in any of its forms, stops the push; the clone is not touched. A well-known shape of secret (a private key block; Anthropic, OpenRouter, OpenAI, GitHub, GitLab, AWS, Google and Slack key formats) is a warning only.
3. **Reported only by `publish` and `stop`.** The other pushes log a hit, as they log a failed push today; a hit there also keeps a clone from being replaced. Because the scan covers the whole branch, the last push of a run reports everything. A `publish` is not tried again after a hit.
4. **History.** A secret removed in a new commit stays in the branch's history, so the next push finds it again. The runner rewrites nothing: it reports the commit, and the agent rewrites its unpushed commits, for example `git reset --soft origin/<branch>` and one new commit. The runner keeps `refs/remotes/origin/<branch>` in the clone at what it last pushed. The app's note, or its next prompt, says so.

## Contract change (for the app repository)

`LastStep`:

- `outcome` gains `secret`, for `publish` and `stop`: the scan found a secret the runner knows; nothing was pushed and no pull request was opened or merged. `error` names the kinds and places, never a value. The app answers `done` with session `paused`, so the next run continues the same clone and session, and blocks the issue with a note naming each kind and place.
- New optional `secrets` (absent: none), at most 50 items, known ones first: `{kind: string ≤ 100, commit: string ≤ 100, path: string ≤ 1000 or null (in the commit's message or author), known: boolean}`. Items with `known: true` come only with `secret`. Items with `known: false` are warnings and may come with any outcome of `publish` or `stop`; the app shows them on the issue.

## Reason

1. Willem chose to build the decided rules in full now rather than inside today's contract (warnings would not reach the issue) or to wait for the app.
2. Push is the one place every push passes through; scanning the branch's own commits rather than only the new ones makes the last report complete and needs no state.
3. Rewriting an agent's history from the runner would be workflow policy and could lose work; the agent owns its commits, and they were never pushed.
