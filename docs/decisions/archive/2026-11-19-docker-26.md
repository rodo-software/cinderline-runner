# Docker Engine 26 or later: an agent mounts only its own clone

- **Status:** Accepted
- **Date:** 2026-11-19
- **Source:** Willem on CLR-207 (security audit of 2026-11-19, finding 5).

## Decision

1. The agent's and the check's containers mount only their issue's folder of the project's runs volume, at the clone's usual path `/runs/<REF>` (`--mount type=volume,...,volume-subpath=<REF>`), next to the repo volume read-only at `/repo`, where the clone's alternates point. The runner's own git containers keep the whole runs volume.
2. The runner requires Docker Engine 26.0 or later (Docker Desktop 4.29 or later), as `volume-subpath` needs it; `add`, `service install` and `run` refuse an older engine. This replaces "25.0.5+ or 23.0.11+" of 2026-11-11-audit-fixes point 6; 26.0 has that CVE fix too.
3. The client state volume, shared by a project's issues, is not changed here.

## Reason

Every clone in the runs volume belongs to the agent's user, so with the whole volume mounted an agent on one issue could edit another issue's paused or kept clone, which the runner later commits and pushes as that issue's work. Engine 25 has been end-of-life since 2024; the alternatives, one runs volume per issue or a subpath only on new engines, were a much larger change or left the hole open on older engines.
